## 1. Why Are We Moving Away From CDN?

Our previous project looked roughly like:

```text
React Fundamentals
│
├── index.html
└── script.js
```

And `index.html` contained CDN scripts:

```html
<script src="[https://unpkg.com/react@18/umd/react.development.js](https://unpkg.com/react@18/umd/react.development.js)"></script>
<script src="[https://unpkg.com/react-dom@18/umd/react-dom.development.js](https://unpkg.com/react-dom@18/umd/react-dom.development.js)"></script>
<script src="[https://unpkg.com/@babel/standalone/babel.min.js](https://unpkg.com/@babel/standalone/babel.min.js)"></script>
```

This was useful for learning the fundamentals. But a real React application needs much more:
* Package management
* Dependency management
* Module imports
* Code transformation
* Bundling
* Development server
* Production builds
* Asset handling
* Optimization

Doing all of this manually would be difficult. This is where **npm** and **bundlers** come in.

---

## 2. What Is npm?

**npm** stands for **Node Package Manager**. It is used to:
* Install JavaScript packages
* Manage project dependencies
* Maintain package versions
* Run project scripts

For example, React itself can be installed through npm:

```bash
npm install react
```

And ReactDOM:

```bash
npm install react-dom
```

Parcel:

```bash
npm install parcel
```

Instead of depending on CDN URLs, our project will have these packages installed locally.

## 5. Understanding `package.json`

Open `package.json`. You will see something similar to:

```json
{
  "name": "04-react-parcel",
  "version": "1.0.0",
  "description": "",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "keywords": [],
  "author": "",
  "license": "ISC"
}
```

`package.json` is the configuration file for our npm project. It stores project metadata, scripts, and dependencies.

> ⚠️ **Common Issue with Parcel:**
> 
> Notice `"main": "index.js"`? If you leave this in when using Parcel for a web app, running `npm start` will throw an error:
> ```text
> 🚨 Build failed. Library targets are not supported in serve mode.
> 💡 The "main" field is meant for libraries, not applications.
> ```
> **Fix:** Delete the `"main": "index.js"` line from `package.json` entirely.

## 9. What Is `node_modules`?

After installing packages, npm creates the `node_modules/` directory.

```text
node_modules/
│
├── react/
├── react-dom/
├── parcel/
└── many other dependencies...
```

* It contains all installed packages and their sub-dependencies.
* **Never manually edit `node_modules`**; it is fully managed and generated by npm.

---

## 10. What Is `package-lock.json`?

`package-lock.json` records the exact versions of every dependency installed.

* `package.json` → High-level project dependencies and version ranges.
* `package-lock.json` → Exact, locked dependency tree.

> **Important:**
> * We **always commit** `package-lock.json` to GitHub.
> * We **never commit** `node_modules/`.

## 12. Why Don't We Push `node_modules`?

`node_modules` contains thousands of files and is very large. Anyone who clones the repository can simply run:

```bash
npm install
```

npm reads `package.json` and `package-lock.json` to recreate `node_modules/` automatically:

```text
GitHub Repo (package.json + package-lock.json)
        ↓
    npm install
        ↓
   node_modules
```

## 15. ES Modules

Instead of relying on global CDN variables (`React`, `ReactDOM`), we now use the standard **ES Module system**:
* `import`
* `export`

---

## 16. The `import` Statement & Why `react-dom/client`?

In `src/main.jsx`:

```javascript
import React from "react";
import ReactDOM from "react-dom/client";
```

> 💡 **Why `react-dom/client` instead of just `react-dom`?**
> * Starting in **React 18+**, React separated DOM rendering into `react-dom/client` (browser) and `react-dom/server` (server-side rendering).
> * Importing from `react-dom/client` unlocks the `createRoot` API and concurrent rendering features.
> * Importing just `react-dom` triggers a deprecation warning and forces legacy React 17 mode.
> * ⚠️ *Watch out for typos: Ensure you don't accidentally write `import React from "react-dom/client"`!*

---

## 17. Creating the React Root

```javascript
const rootElement = document.getElementById("root");
const root = ReactDOM.createRoot(rootElement);
```

1. JavaScript finds the container: `document.getElementById("root")`
2. React initializes the root: `ReactDOM.createRoot(rootElement)`

---

## 18. Rendering JSX

```jsx
import React from "react";
import ReactDOM from "react-dom/client";

const rootElement = document.getElementById("root");
const root = ReactDOM.createRoot(rootElement);

    <h1>Hello React</h1>
);

```

## 19. Why Does JSX Work Without Babel CDN?

Parcel automatically compiles JSX into standard JavaScript during build time:

```text
main.jsx (JSX)
    ↓
  Parcel
    ↓
Transpiled JS + Bundled Modules
    ↓
 Browser (DOM rendered)
```

## 23. CommonJS vs. ES Modules

| Feature | CommonJS (Node.js traditional) | ES Modules (Modern Standard) |
| :--- | :--- | :--- |
| **Import** | `const x = require('./x')` | `import x from './x'` |
| **Export** | `module.exports = x` | `export default x` or `export { x }` |
| **Usage** | Node / Backend | Modern Frontend & React |

## 26. Default vs. Named Exports

### Default Export
```jsx
// Export
export default Header;

// Import (can be named anything)
import Header from "./components/Header.jsx";
import MyHeader from "./components/Header.jsx";
```

### Named Export
```jsx
// Export
export { Header, Footer };

// Import (must use exact names in curly braces)
import { Header, Footer } from "./components/Layout.jsx";
```

## 27. Complete Practical Application

### `src/components/Header.jsx`
```jsx
function Header() {
    return (
        <header>
            <h1>React Store</h1>
            <p>Welcome to our store</p>
        </header>
    );
}

export default Header;
```

### `src/components/Product.jsx`
```jsx
function Product(props) {
    return (
        <div>
            <h2>{props.name}</h2>
            <p>Price: ₹{props.price}</p>
            <p>Category: {props.category}</p>
        </div>
    );
}

export default Product;
```

### `src/main.jsx`
```jsx
import React from "react";
import ReactDOM from "react-dom/client";
import Header from "./components/Header.jsx";
import Product from "./components/Product.jsx";

const rootElement = document.getElementById("root");
const root = ReactDOM.createRoot(rootElement);

const products = [
    {
        id: 1,
        name: "Laptop",
        price: 50000,
        category: "Electronics"
    },
    {
        id: 2,
        name: "Phone",
        price: 30000,
        category: "Electronics"
    },
    {
        id: 3,
        name: "Keyboard",
        price: 2000,
        category: "Accessories"
    }
];

function App() {
    return (
        <div>
            <Header/>
            <main>
                {products.map((product) => (
                    <Product category="{product.category}" key="{product.id}" name="{product.name}" price="{product.price}"/>
                ))}
            </main>
        </div>
    );
}

root.render(<App/>);
```

## 2. Development Build

When we run `npm start`, we are working with a **development build**. 
The purpose of a development build is to make coding easier. We want:
* Fast development
* Useful error messages
* Easy debugging
* Fast updates (Hot Reloading) while coding

The development flow:
**Source Code** ↓ **Parcel** ↓ **Development Build** ↓ **Development Server** ↓ **Browser**

---

## 3. Why Do We Need a Production Build?

The development environment is designed for developers. When we deploy our application, we don't want to send our raw, unoptimized development project directly to users. 

We want an optimized build:
**Development Code** ↓ **Optimization & Bundling** ↓ **Production Build** ↓ **Deployment**

---

## 4. Creating a Production Build

Add a `build` script to `package.json`:

```json
{
    "scripts": {
        "start": "parcel index.html",
        "build": "parcel build index.html"
    }
}
```

Now run:
```bash
npm run build
```
Parcel will process your code and create a highly optimized production build.

---

## 5. The `dist/` Folder

After running `npm run build`, you will see a new directory called `dist/` (which stands for **distribution**). It contains the final, minified files generated by the build process.

The relationship is:
**`src/` (Source Code)** ↓ **Parcel** ↓ **`dist/` (Generated Build)**

---

## 6. Should We Commit `dist/` to GitHub?

No. We don't need to track generated build output in Git because anyone can recreate it by running `npm run build`.

Update your `.gitignore` to include `dist/` and `.parcel-cache/`:

```gitignore
node_modules/
dist/
.parcel-cache/
```

> 💡 **What is `.parcel-cache/`?** 
> Parcel uses this directory to cache information that speeds up development and building. We don't need to commit this either.

## 7. CSS in React: Global Stylesheet

Let's add styling. Create `src/styles/Global.css`:

```css
body {
    margin: 0;
    font-family: Arial, sans-serif;
}

h1 {
    color: blue;
}
```

Import the stylesheet inside `src/main.jsx`:

```jsx
import "./styles/Global.css";
```

**The Problem with Global CSS:**
Global CSS affects *every* matching element in the app. If you style a `button` in `global.css`, every single button (Header button, Login button, Search button) will get that style. As apps grow, this becomes very hard to manage.

---

## 8. Component-Level Stylesheet

We can create a CSS file just for a component, like `src/components/Header.css`:

```css
.header {
    padding: 20px;
    background: #eeeeee;
}
```

Import it directly into `Header.jsx`:

```jsx
import "./Header.css";

function Header() {
    return (
        <header className="header">
            <h1>React Store</h1>
        </header>
    );
}
```

> ⚠️ **Common Gotcha: `className` vs `class`**
> In normal HTML, we write `<div class="header">`. 
> In JSX, `class` is a reserved JavaScript keyword, so we **must** use `<div className="header">`.

**Wait, Component-Level CSS is still Global!**
Even though we created `Header.css`, the `.header` class is still a normal, global CSS class. If another component uses `<div className="header">`, it will accidentally receive the same styles! 

---

## 9. CSS Modules (The Fix for CSS Collisions)

To actually scope our CSS so it only affects one component, we use **CSS Modules**. 
Rename the file to `Header.module.css`:

```css
.header {
    padding: 20px;
    background: #eeeeee;
}

.title {
    margin: 0;
}
```

Now, import and use it differently in `Header.jsx`:

```jsx
import styles from "./Header.module.css";

function Header() {
    return (
        <header className={styles.header}>
            <h1 className={styles.title}>
                React Store
            </h1>
        </header>
    );
}
```

**What is happening here?** 
Parcel generates a unique, scoped class name for `.header` behind the scenes (e.g., `Header_header__1a2b3c`). This guarantees your class names will never collide with other components!

---

## 10. Inline Styling

React also allows styles to be applied directly to an element using a JavaScript object.

```jsx
<h1 style={{ color: "blue", fontSize: "32px" }}>
    React Store
</h1>
```

> 💡 **Why `fontSize` and not `font-size`?**
> Because the style is a JavaScript object, we cannot use hyphens (which mean subtraction in JS). We must write all CSS properties in **camelCase** (e.g., `backgroundColor`, `fontSize`, `marginTop`).

You can also pull this out into a variable since it's just JavaScript:

```jsx
const titleStyle = {
    color: "blue",
    fontSize: "32px"
};

function Header() {
    return <h1 style={titleStyle}>React Store</h1>;
}
```

---

## 11. When to Use Which Styling Approach?

| Approach | When to use it |
| :--- | :--- |
| **Global CSS** (`Global.css`) | Application-wide resets (e.g., body margins, fonts). |
| **Component CSS** (`.css`) | Styles associated with a specific component (but beware of global collisions). |
| **CSS Modules** (`.module.css`) | Component styles where scoped, unique class names are required to avoid bugs. |
| **Inline Styles** (`style={{...}}`) | Small or dynamic styles directly controlled by JavaScript logic. |

## 12. Final Practical Project Structure

Here is our completely organized project:

### `src/styles/Global.css`
```css
body {
    margin: 0;
    font-family: Arial, sans-serif;
}
* {
    box-sizing: border-box;
}
```

### `src/components/Header.module.css`
```css
.header {
    padding: 20px;
    background: #eeeeee;
}
.title {
    margin: 0;
}
```

### `src/components/Header.jsx`
```jsx
import styles from "./Header.module.css";

function Header() {
    return (
        <header className={styles.header}>
            <h1 className={styles.title}>
                React Store
            </h1>
        </header>
    );
}
export default Header;
```

### `src/components/Product.jsx`
```jsx
function Product(props) {
    return (
        <div>
            <h2>{props.name}</h2>
            <p>Price: ₹{props.price}</p>
            <p>Category: {props.category}</p>
        </div>
    );
}
export default Product;
```

### `src/main.jsx`
```jsx
import React from "react";
import ReactDOM from "react-dom/client";
import Header from "./components/Header.jsx";
import Product from "./components/Product.jsx";
import "./styles/Global.css";

const rootElement = document.getElementById("root");
const root = ReactDOM.createRoot(rootElement);

const products = [
    { name: "Laptop", price: 50000, category: "Electronics" },
    { name: "Phone", price: 30000, category: "Electronics" },
    { name: "Keyboard", price: 2000, category: "Accessories" }
];

function App() {
    return (
        <div>
            <Header/>
            <main>
                {products.map((product) => {
                    return (
                        <Product category={product.category} key={product.name} name={product.name} price={product.price}/>
                    );
                })}
            </main>
        </div>
    );
}

root.render(<App/>);
```
*(Note: Always remember to add a unique `key` prop when mapping over arrays, as learned in Lecture 3!)*
